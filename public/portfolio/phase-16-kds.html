Phase 16 · Real-Time KDS & Live Alerts

Operational Excellence for the Kitchen

Transform the admin dashboard into a real restaurant tool. Build a dedicated Kitchen Display System (KDS) that receives live order updates, plays audio alerts, and operates independently of the analytics dashboard.

1 Overview

Goal: In a real restaurant, chefs do not want to look at revenue charts or user management tables. They need a high-contrast, zero-distraction screen that shows incoming orders and allows one-tap status updates.

Key Deliverables

  • New Status: Added READY to the order lifecycle (PENDING → PAID → PREPARING → READY → DELIVERED).
  • Kitchen UI: A dark-mode page (/admin/kitchen) with large, touch-friendly cards.
  • Real-Time Sync: The board updates automatically when a customer pays—no manual refresh required.
  • Audio Alerts: A dynamic "ding" sound plays when a new order arrives.
  • Smart Localization: The KDS displays dish names in English on non-Arabic pages, and Arabic on Arabic pages.

2 Real-Time Architecture (The Serverless Trap)

The original plan was to use a Node.js EventEmitter. When the Stripe webhook fired, it would emit an event, and the SSE stream would catch it.

Why EventEmitters fail in Next.js Serverless

Next.js isolates API routes into separate execution contexts. The webhook and the SSE route are completely different instances and cannot share memory. On Vercel, they might even run on different servers.

The Robust Solution: SSE + DB Polling

We implemented a Server-Sent Event (SSE) stream that keeps the client connection open, but the server polls the database every 4 seconds for new orders.

// src/app/api/admin/orders/stream/route.ts
const pollInterval = setInterval(async () => {
  const newOrders = await prisma.order.findMany({
    where: {
      status: "PAID",
      updatedAt: { gt: lastCheck },
    },
    include: { items: true },
  });

  if (newOrders.length > 0) {
    lastCheck = new Date();
    newOrders.forEach((order) => {
      sendEvent({ type: "new-order", order });
    });
  }
}, 4000);
Keep-Alive Ping To prevent Vercel from closing the connection after 10 seconds, we send a : keep-alive\n\n comment every 10 seconds.

3 The Kitchen Display System

The KDS is completely separate from the main Admin Dashboard. It only fetches orders with a status of PAID or PREPARING.

Optimistic UI

When a chef clicks "Start Cooking", the UI updates instantly while the database query runs in the background. This makes the tablet feel native and responsive.

const handleUpdate = async (id: string, newStatus: string) => {
  // Optimistic update: change UI immediately
  setOrders((prev) => 
    newStatus === "READY" 
      ? prev.filter((o) => o.id !== id) // Remove from board
      : prev.map((o) => o.id === id ? { ...o, status: newStatus } : o)
  );

  // Send actual DB update
  await updateOrderStatus(id, newStatus as "PREPARING" | "READY");
};

4 Audio Alerts (Web Audio API)

We didn't want to rely on external MP3 files (which require downloading and can be blocked by browsers). Instead, we generated a "ding" sound mathematically using the browser's native Web Audio API.

const playDing = () => {
  if (!soundEnabled) return;
  const AudioContextClass = window.AudioContext || (window as any).webkitAudioContext;
  const ctx = new AudioContextClass();
  
  const osc = ctx.createOscillator();
  const gain = ctx.createGain();
  
  osc.type = "sine";
  osc.frequency.setValueAtTime(880, ctx.currentTime); // A5 note
  osc.frequency.exponentialRampToValueAtTime(440, ctx.currentTime + 0.5);
  
  gain.gain.setValueAtTime(0.5, ctx.currentTime);
  gain.gain.exponentialRampToValueAtTime(0.01, ctx.currentTime + 1);
  
  osc.connect(gain);
  gain.connect(ctx.destination);
  
  osc.start();
  osc.stop(ctx.currentTime + 1);
};
Browser Autoplay Policy Browsers block audio until the user interacts with the page. We added a "Enable Sound" button that acts as the required user interaction to unlock the audio context.

5 Admin Localization

The KDS and the Admin Orders page must display dish names in English for English users, and Arabic for Arabic users.

We created a pure helper function getLocalizedName that checks the current locale and returns the correct column from the database.

// src/lib/utils/locale.ts
export function getLocalizedName(name: string, nameEn: string | null, locale: string) {
  if (locale === "ar") return name;
  return nameEn ?? name;
}

We then updated the Prisma queries to fetch nameEn alongside name, ensuring the client component has all the data it needs to render perfectly.

6 Engineering Lessons

  • Serverless isolation is real. In-memory event emitters do not work across API routes in Next.js. DB polling + SSE is the most robust solution without paying for Pusher/Ably.
  • Web Audio API is powerful. Generating sounds dynamically removes external asset dependencies and network requests, making the KDS faster and more reliable.
  • Optimistic UI is essential for operations. In a busy kitchen, a 500ms delay between clicking "Start Cooking" and seeing the UI update feels broken. Always update the UI immediately, then sync with the server.
  • Admin UX matters. Chefs and managers are users too. A dedicated, high-contrast KDS is infinitely better than a cramped table view.
