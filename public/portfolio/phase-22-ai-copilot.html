1 Overview

Goal: Provide restaurant owners with a "Senior Consultant" in their pocket. Instead of hardcoding dashboards for every question, an LLM can analyze complex relationships (e.g., "Why did revenue drop?" or "What are my top items?").

Key Deliverables

  • Bring Your Own Key (BYOK): The admin inputs their own API key via the Settings page.
  • Multi-Provider: Support for Google Gemini, OpenAI, and DeepSeek out of the box.
  • Quick Actions: One-click UI buttons to instantly ask about Revenue, Top Items, or Low Stock.
  • Global Localization: The AI responds in the admin's active locale, including full RTL formatting for Arabic.
  • Context Awareness: The AI accurately answers questions about Lumière's real data without hallucinating.

2 Architecture & Token Optimization

Sending raw database rows to an LLM causes token exhaustion and privacy leaks. We built an aggregation pipeline that summarizes the data using Prisma before the AI sees it.

// src/lib/ai/context.ts
const [revenueAgg, topItemsAgg, lowStockRaw] = await Promise.all([
  prisma.order.aggregate({
    where: { status: { in: ["PAID", "PREPARING", "READY", "DELIVERED"] } },
    _sum: { totalAmount: true },
    _count: true,
  }),
  prisma.orderItem.groupBy({
    by: ["menuItemId"],
    _sum: { quantity: true },
    orderBy: { _sum: { quantity: "desc" } },
    take: 5,
  }),
]);
System Prompt Engineering The aggregated JSON is injected into the system prompt. We explicitly instructed the AI to: "Use only the numbers in the Live Data section. Never invent or extrapolate." This eliminates AI hallucinations.

3 BYOK Security (AES-256-GCM)

Security was the highest priority. Admin API keys are extremely sensitive, and a leak could cost thousands of dollars. The key is encrypted at rest and only decrypted on the server.

// src/lib/crypto.ts
export function encrypt(plaintext: string): string {
  const iv = randomBytes(12);
  const cipher = createCipheriv("aes-256-gcm", getKey(), iv);
  const ciphertext = Buffer.concat([cipher.update(plaintext, "utf8"), cipher.final()]);
  const tag = cipher.getAuthTag();
  
  // Packs [IV][Tag][Ciphertext] into one Base64 string
  return Buffer.concat([iv, tag, ciphertext]).toString("base64");
}
Zero Client Exposure The decrypted key never reaches the browser. It is only decrypted inside the Next.js API Route (/api/admin/ai/chat) immediately before calling the LLM provider.

4 Overcoming Google API Hurdles

Integrating Google Gemini proved to be the hardest part of this phase due to breaking API changes.

1. The "AQ." Key Format

Google changed their API key format from AIzaSy... to AQ.Ab8R.... The Vercel AI SDK v5 handles the header transport, but our custom "Test Connection" function was failing.

2. Gemini 3.x Thinking Timeouts

Newer models use an internal Chain-of-Thought "thinking" phase before generating the first token. Our original test used generateText, which caused a 20-second timeout while waiting for the AI to finish thinking.

The Fix: HTTP Probes & Thinking Levels

We replaced the text generation test with a raw fetch probe (GET /v1beta/models/{model}) which validates the key in 0.2 seconds.

For the actual chat, we forced thinkingLevel: "low" in the providerOptions so the AI streams responses immediately.

// src/lib/ai/provider.ts
if (provider === "google" && modelId.startsWith("gemini-3")) {
  return { google: { thinkingConfig: { thinkingLevel: "low" } } };
}

5 Engineering Lessons

  • Memoize the Transport: In Vercel AI SDK v5, passing transport: new DefaultChatTransport(...) directly to useChat causes infinite re-renders. It must be wrapped in useMemo.
  • Token Economics: Never send raw table rows to an LLM. Use Prisma groupBy and aggregate to send compact JSON snapshots.
  • Probes vs. Generation: When validating API keys, use a lightweight HTTP probe. Generating text is slow, costs money, and is prone to timeouts.
  • Graceful Degradation: Always wrap the AI chat in a try/catch block. If a model is overloaded (503), display a friendly error to the user and suggest switching models in the dropdown.
