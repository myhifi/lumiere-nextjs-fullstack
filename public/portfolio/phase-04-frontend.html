Server Components, RTL Layout & Interactive Menu UI

Build the customer-facing UI using Next.js Server Components for zero-JS data rendering, with minimal Client Components only where interactivity is required. The result: 5 Server Components, 1 Client Component, zero fetch calls to the internal API.

Server ComponentsClient Components RTL ArabicTailwind v4 URL StateDynamic Routes

1 Overview

Goal: Render the database through an elegant, RTL, mobile-responsive interface where only the small interactive parts ship JavaScript to the browser.

Deliverables

  1. RTL Arabic layout with sticky Navbar and Lumière branding.
  2. /menu page rendering 12 items via Server Component + Prisma.
  3. MenuItemCard reusable component (grid-aligned, hover-animated).
  4. CategoryFilter — a Client Component that filters via URL searchParams.
  5. /menu/[slug] detail page with dynamic routing.
  6. Custom not-found.tsx for elegant 404s.

2 Architectural Decision — Server vs Client Components

The core Next.js 16 mental model:

AspectServer ComponentClient Component
Executes onServerBrowser
Direct Prisma access✅ Yes❌ No (must fetch)
useState / useEffect❌ Forbidden✅ Allowed
onClick / onChange❌ Forbidden✅ Allowed
JS shipped to browserZeroFull bundle
Default in App Router✅ YesOpt-in via "use client"
Rule of thumb Keep everything Server. Convert only the smallest interactive leaf to Client.

Engineering rationale: Every Client Component adds JS bytes to the browser bundle. On slow connections, more JS = slower Time-to-Interactive. Server Components deliver HTML with zero hydration cost.

3 Component Tree for /menu

📄 page.tsx SERVER Queries Prisma directly
├─ Navbar SERVER Static links
├─ CategoryFilter CLIENT ⚡ URL updates on click
└─ MenuItemCard × 12 SERVER Static render, zero JS

WHY this split:

  • Only CategoryFilter needs interactivity → only it becomes Client.
  • MenuItemCard is pure presentation → stays Server, ships 0 bytes.
  • The page itself stays Server → direct Prisma query, no fetch.
Anti-pattern avoided Marking /menu/page.tsx as "use client" — that would force all 12 cards to ship JS and require an HTTP call to /api/menu/items.

6 Why components/ Cannot Live Inside app/

The phantom route problem:

src/app/components/layout/Navbar.tsx
        ^^^^^^^^^^
        treated as a URL segment

Next.js App Router generates routes from folder names. A folder src/app/components/ is interpreted as the URL prefix /components/. Even though Navbar.tsx isn't a page.tsx, developers will:

  • Waste time debugging why /components/layout/Navbar returns 404.
  • Accidentally create conflicting routes.

The fix: Move components/ up one level to src/components/.

Verified in Phase 4 src/app/ → URLs only · src/components/ → React components · src/lib/ → logic · src/generated/ → Prisma Client

12 Navbar Deep-Dive — Sticky & Backdrop Blur

sticky top-0 z-50

  • sticky — element scrolls with page, then sticks at top: 0.
  • z-50 — stacks above page content (Tailwind scale 0–50).
  • WHY: Modern UX expects persistent navigation; users reach any page in one click.

bg-background/85 backdrop-blur-md

  • bg-background/85 — 85% opacity background.
  • backdrop-blur-md — Gaussian blur of content behind the header.
  • WHY: Content scrolls under the header but stays partially visible — a premium iOS/macOS aesthetic.

max-w-6xl mx-auto

Constrains content to 1152px and centers it. WHY: Prevents stretched text on ultra-wide monitors.

as const on navLinks

Freezes the array literal — TypeScript narrows string types. WHY: Typos in href become compile errors.

14 Card Deep-Dive — Key Techniques

group + group-hover:

Parent gets group class; children react to group-hover:*. WHY: Hover on any part of the card animates all children (image zoom, text color, border).

aspect-4/3

New Tailwind v4 syntax for aspect-ratio: 4 / 3. Replaces aspect-[4/3]. WHY: Uniform image heights keep grid rows aligned.

fill on <Image>

Image fills its parent container absolutely. Requires parent with position: relative + fixed dimensions. WHY: Enables object-cover (crop to fit) instead of distortion.

sizes="(max-width: 768px) 100vw, 33vw"

Tells Next.js how wide the image renders. WHY: Generates optimal srcset — mobile downloads smaller images.

line-clamp-2

Truncates text after 2 lines with ellipsis. WHY: Prevents variable-length descriptions from breaking grid uniformity.

mt-auto

Pushes price to card bottom. WHY: Cards with short descriptions still align prices at the bottom.

15 Menu Page — Full File

import { prisma } from "@/lib/prisma";
import { MenuItemCard } from "@/components/menu/MenuItemCard";
import { CategoryFilter } from "@/components/menu/CategoryFilter";

type MenuPageProps = {
  searchParams: Promise<{ category?: string }>;
};

export default async function MenuPage({ searchParams }: MenuPageProps) {
  const { category } = await searchParams;

  const [categories, items] = await Promise.all([
    prisma.category.findMany({
      orderBy: { displayOrder: "asc" },
      select: { id: true, name: true, slug: true },
    }),
    prisma.menuItem.findMany({
      where: {
        isAvailable: true,
        ...(category && { category: { slug: category } }),
      },
      orderBy: [{ isFeatured: "desc" }, { name: "asc" }],
      include: { category: { select: { name: true, slug: true } } },
    }),
  ]);

  return (
    <div className="max-w-6xl mx-auto px-4 py-12">
      <div className="text-center mb-12">
        <span className="text-accent text-sm font-medium tracking-widest">OUR MENU</span>
        <h1 className="text-4xl md:text-5xl font-bold mt-3 mb-4">قائمة Lumière</h1>
        <p className="text-muted max-w-xl mx-auto">
          مجموعة مختارة بعناية من أشهى الأطباق، مُعدّة بأجود المكونات
        </p>
      </div>

      <CategoryFilter categories={categories} />

      {items.length === 0 ? (
        <p className="text-center text-muted py-16">
          لا توجد أطباق في هذا التصنيف حالياً.
        </p>
      ) : (
        <div className="grid grid-cols-1 sm:grid-cols-2 lg:grid-cols-3 gap-6">
          {items.map((item) => (
            <MenuItemCard key={item.id} item={item} />
          ))}
        </div>
      )}
    </div>
  );
}

16 Menu Page Deep-Dive — searchParams & Promise.all

searchParams: Promise<{ category?: string }>

  • Next.js 15+ passes searchParams as an async value.
  • Must await before destructuring.
  • WHY this change: Enables streaming — the page shell renders before params resolve.

Promise.all([...])

  • Fires both Prisma queries concurrently.
  • Total latency = max(query1, query2) instead of query1 + query2.
  • WHY: SQLite handles concurrent reads; no reason to serialize.

Conditional spread

...(category && { category: { slug: category } })
  • If category exists → adds filter.
  • If undefined → spreads false, which Prisma ignores.
  • WHY: One query handles both "all items" and "filtered items" without branching.
Zero-JS verification Open DevTools → Network. The /menu request returns Content-Type: text/html. No fetch('/api/menu/items') call exists. This is the Server Component advantage in action.

17 CategoryFilter — Client Component

"use client";

import { useRouter, useSearchParams, usePathname } from "next/navigation";

type Category = { id: string; name: string; slug: string };

export function CategoryFilter({ categories }: { categories: Category[] }) {
  const router = useRouter();
  const pathname = usePathname();
  const searchParams = useSearchParams();
  const activeSlug = searchParams.get("category");

  function handleFilter(slug: string | null) {
    const params = new URLSearchParams(searchParams.toString());
    if (slug) {
      params.set("category", slug);
    } else {
      params.delete("category");
    }
    router.push(`${pathname}?${params.toString()}`);
  }

  return (
    <div className="flex flex-wrap items-center justify-center gap-2 mb-10">
      <FilterButton label="الكل" isActive={!activeSlug} onClick={() => handleFilter(null)} />
      {categories.map((cat) => (
        <FilterButton key={cat.id} label={cat.name}
          isActive={activeSlug === cat.slug}
          onClick={() => handleFilter(cat.slug)} />
      ))}
    </div>
  );
}

function FilterButton({ label, isActive, onClick }: { label: string; isActive: boolean; onClick: () => void }) {
  return (
    <button type="button" onClick={onClick}
      className={`px-5 py-2 rounded-full text-sm font-medium border transition-all ${
        isActive
          ? "bg-accent text-white border-accent shadow-sm"
          : "bg-card text-foreground border-border hover:border-accent hover:text-accent"
      }`}>
      {label}
    </button>
  );
}

20 notFound() & Custom 404

params: Promise<{ slug: string }> — Next.js 15+ async params. await params before use. WHY: Enables parallel rendering of layout + page.

notFound()

  • Throws NEXT_NOT_FOUND — Next.js catches it and renders the nearest not-found.tsx.
  • Automatically sets HTTP status to 404.
  • WHY explicit call: findUnique returns null when not found; without notFound(), the page would try to render item.name on null → runtime crash → 500.

21 Request Data Flow

Trace of GET /menu?category=desserts:

1. User navigates to /menu
2. Server Component <MenuPage /> executes:
await searchParams → { category: undefined }
3. Promise.all fires:
• prisma.category.findMany() (4 rows)
• prisma.menuItem.findMany({ where: { isAvailable: true } })
4. React streams HTML with 12 <MenuItemCard /> + <CategoryFilter />
5. Filter buttons hydrate — click "حلويات"
6. router.push("/menu?category=desserts")
7. Next.js re-runs <MenuPage /> with new searchParams
8. Streamed HTML replaces previous grid (3 desserts)

Boundary rationale: Data crosses from SQLite → Prisma → React tree → HTML string → browser DOM. Each step is typed; any shape mismatch fails at compile time.

23 Server vs Client — Decision Cheat Sheet

Ask these questions in order:

  1. Does the component fetch data from Prisma? → Server
  2. Does it use useState, useEffect, useRef? → Client
  3. Does it attach event handlers (onClick, onSubmit)? → Client
  4. Does it access window, localStorage, document? → Client
  5. Otherwise → Server (default)
