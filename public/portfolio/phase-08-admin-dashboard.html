Performance rationale Six independent queries run in parallel → total latency ≈ slowest query instead of sum of all six. Typical improvement: 500ms instead of 3s.

6 Server Actions Pattern — Across All 5 Entities

Every CRUD operation follows an identical structure:

"use server";

// 1. Authorization guard
async function requireAdmin() {
  const session = await auth();
  if (!session?.user) return null;
  if (session.user.role !== "ADMIN" && session.user.role !== "STAFF") return null;
  return session.user;
}

// 2. The action
export async function someAction(input: unknown) {
  const user = await requireAdmin();
  if (!user) return { success: false, error: "غير مصرح" };

  // 3. Zod validation
  const parsed = schema.safeParse(input);
  if (!parsed.success) return { success: false, error: "تحقق من البيانات", fieldErrors };

  try {
    // 4. Prisma mutation
    await prisma.model.create / update / delete(...);

    // 5. Cache invalidation
    revalidatePath("/admin/...");
    revalidatePath("/menu");
    revalidatePath("/");
    return { success: true, id };
  } catch (error) {
    console.error("[someAction]", error);
    return { success: false, error: "فشل الإجراء" };
  }
}

Why revalidatePath?

PathInvalidated when
/admin/<section>Always — refresh the admin list
/adminWhen counters change
/menuWhen items / categories change
/When featured items change
Zero manual refetch After a Server Action completes, Next.js purges the cached HTML for the listed paths. The next browser request re-runs the Server Components with fresh data — no router.refresh() required for the affected paths.

Dual filtering

Two independent filter bars — by category and by availability. Both preserved in URL:

/admin/menu?category=desserts&availability=available

function buildURL(params) {
  const qs = new URLSearchParams();
  if (params.category) qs.set("category", params.category);
  if (params.availability) qs.set("availability", params.availability);
  return `/admin/menu${qs.toString() ? `?${qs}` : ""}`;
}

Why buildURL: Each filter link preserves the other filter's value — clicking "متاح" while filtered by "حلويات" keeps the category filter intact.

Auto-slugify from English name

function slugify(text: string): string {
  return text
    .toLowerCase()
    .trim()
    .replace(/[^a-z0-9\s-]/g, "")
    .replace(/\s+/g, "-")
    .replace(/-+/g, "-");
}

Behavior:

  • In "new" mode: slug regenerates with every keystroke in the name field.
  • In "edit" mode: slug stays frozen — protects existing URLs from silent changes.
  • Arabic names: slugify strips all Arabic characters → admin enters slug manually (common pattern).

Duplicate slug detection

const duplicate = await prisma.menuItem.findFirst({
  where: { slug: data.slug, NOT: { id: itemId } },
});
// NOT clause prevents matching the item against itself in edit mode

11 Cascade Protection — Category Deletion

The hidden trap In Phase 2 we set onDelete: Cascade on MenuItem.category. Deleting a category therefore deletes all its items silently. This is correct for referential integrity but devastating in production if a user clicks "Delete" casually.

The guard

const itemsCount = await prisma.menuItem.count({ where: { categoryId: id } });
if (itemsCount > 0) {
  return {
    success: false,
    error: `لا يمكن حذف التصنيف — يحتوي على ${itemsCount} طبق. انقل الأطباق لتصنيف آخر أولاً.`,
  };
}

Verification from dev.log:

deleteCategory("...")  in 25ms    ← protection rejected instantly (fail-fast)
deleteCategory("...")  in 629ms   ← empty category actually deleted
Fail-fast principle The 25ms response proves the guard runs before any database write — no wasted work, no risk of a partial delete.

12 Tables Management

Same CRUD pattern with one critical safety rule: tables with reservation history cannot be deleted.

Fields

  • number — unique integer (1, 2, 3...)
  • capacity — number of seats
  • location — enum-like string (Indoor, Window, Outdoor, VIP)
  • isActive — enable/disable without deletion

Toggle instead of delete

Disabled tables stop being considered by the Phase 5 booking engine but remain in the database for historical queries. The isActive flag is the primary lifecycle tool.

13 Reservation-History Protection

const reservationsCount = await prisma.reservation.count({ where: { tableId: id } });
if (reservationsCount > 0) {
  return {
    success: false,
    error: `لا يمكن حذف الطاولة — لها ${reservationsCount} حجز تاريخي. عطّلها بدلاً من ذلك.`,
  };
}

Why stricter than categories?

EntityDeletion allowed whenReason
CategoryZero current itemsItems can be reassigned
TableZero historical reservationsReservations are financial records
Business reality A deleted category leaves items easy to reassign. A deleted table orphans financial records — potentially a tax/legal problem. Stricter for a reason.

14 Users Management — Admin Only

Only users with role === "ADMIN" can access /admin/users. All other roles are redirected to /admin.

Fields

  • email — unique, set at creation, immutable afterward
  • name — display name
  • role — ADMIN or STAFF
  • isActive — soft-disable without deleting
  • password / newPassword — creation requires it, edit makes it optional

Why email is immutable

The email is the login identifier. Changing it would invalidate the target user's active session without warning. A safe policy: keep it fixed, create a new user if the email must change.

15 Three Safety Layers in User Management

1
if (id === admin.id && data.role !== "ADMIN") return error;
You cannot remove your own admin role.
2
if (id === admin.id && !data.isActive) return error;
You cannot disable your own account.
3
const otherActiveAdmins = await prisma.user.count({ where: { role: "ADMIN", isActive: true, NOT: { id } } });
You cannot remove the last active admin — locks the entire system out.
Combined effect These three rules make it impossible to accidentally lock the system out of admin access, no matter what combination of role changes or deletions is attempted.

19 Loading & Error Boundaries

Next.js recognizes two special file names per route segment:

FileWhen rendered
loading.tsxWhile the route segment's data is being fetched (React Suspense boundary).
error.tsxWhen the segment throws an error. Must be a Client Component (uses reset).

Files placed

src/app/admin/loading.tsxNEW

Renders LoadingSpinner while admin pages fetch.

src/app/admin/error.tsxNEW

Renders ErrorFallback when an admin page throws.

src/app/(public)/loading.tsxNEW

Loading state for public pages.

src/app/(public)/error.tsxNEW

Error fallback for public pages.

Automatic wiring No imports needed in parent layouts. Next.js discovers these files by name and inserts them into the render tree automatically.

2. handleStatus("CONFIRMED") wraps in startTransition
→ setIsPending(true)
3. Server Action invoked: updateReservationStatus(id, "CONFIRMED")
─── SERVER ───
4. requireAdmin() — session verified
5. prisma.reservation.update({ data: { status: "CONFIRMED" } })
6. revalidatePath("/admin/reservations")
7. revalidatePath("/admin")
8. Return { success: true }
─── CLIENT ───
9. isPending back to false · Row re-renders with new status badge

Total latency: ~500-800ms including network, DB write, cache invalidation, and DOM update.

21 Defense-in-Depth — Five Layers

Layer 1 · Client Guard — Buttons hidden by role (isAdmin prop). No security, only UX.
Layer 2 · Edge Middleware — Redirects unauthenticated users away from /admin/* before any page loads.
Layer 3 · Layout Guard — admin/layout.tsx verifies the session — safety net if middleware is bypassed.
Layer 4 · Server Action Guard — requireAdmin() runs on every mutation. Cannot be bypassed — the code lives server-side.
Layer 5 · Business Rule Guard — Cascade protection, reservation-history checks, and last-admin rule prevent destructive mistakes.
Why so many layers Each layer can fail independently (misconfiguration, middleware exception, session race). Defense-in-depth ensures no single point of failure compromises authorization.
