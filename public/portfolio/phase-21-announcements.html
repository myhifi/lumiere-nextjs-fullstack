Phase 21 · Admin Communications & Engine

SaaS-Grade Admin Experience

Transform the admin dashboard into a communication hub. Implement a CRUD announcement system, an automated alert engine with custom rules, and a self-serve interactive User Guide.

1 Overview

Goal: Give the restaurant manager full control over communication. Instead of hardcoding automated alerts, the admin can define custom thresholds, create manual announcements, and access a full guide on how to use the system.

Key Deliverables

  • Announcements CRUD: Manual alerts visible across all admin pages (with dismiss functionality).
  • System Rules Engine: Automated alerts triggered by database conditions (Low Stock, High Order Value, Pending Reservations).
  • Built-in vs Custom Rules: Protection for default rules (Reset only) and full CRUD for custom rules.
  • Help & User Guide: An interactive accordion page that documents every feature for the users.

2 Announcements Manager

We built a complete CRUD interface at /admin/announcements. It allows Admins to publish alerts with different types (INFO, WARNING, SUCCESS, URGENT) and optional expiry dates.

Global Banner UI Alerts are fetched in the admin layout and displayed at the top of every page. We optimized the UX by limiting the display to the top 3 alerts with a scrollbar and a "Clear All" button to prevent the page from being flooded.

3 System Auto-Rules Engine

This is the core intelligence of Phase 21. The admin can create custom rules in the database (e.g., "Alert me when stock is <= 10"). The SystemAlertEngine runs every time the Announcements page loads, checks the rules against live database data, and generates "AUTO" alerts.

// src/lib/services/system-alerts.ts
const rules = await prisma.systemRule.findMany({ where: { isActive: true } });
for (const rule of rules) {
  if (rule.metric === "STOCK_LEVEL") { ... }
  if (rule.metric === "ORDER_TOTAL") { ... }
}
Idempotency & Upsert To prevent creating duplicate alerts every time the page loads, we use a triggerKey (e.g., low_stock_{id}_{threshold}). The engine uses prisma.announcement.upsert to ensure the same alert is only created once per condition.

4 Help & User Guide

To make the platform truly self-serve, we added a /admin/help page. It features an interactive accordion that explains every feature (Overview, Orders, KDS, Menu, etc.) with step-by-step instructions and examples.

This is built using a reusable HelpAccordion Client Component and translated dynamically via next-intl, ensuring it works perfectly in both English and Arabic.

5 Engineering Lessons

  • React State vs Props: When updating a list item (like toggling a rule), relying on local useState initialized from props will fail to update the UI. Always read directly from props for view mode, and only use state for the edit form.
  • Flexbox Overflow: In narrow columns, trying to fit text and buttons horizontally causes clipping. Switching the parent container to flex flex-col guarantees the buttons stack neatly and remain fully visible.
  • Data Validation is Key: Zod schemas must include every required field. Forgetting to pass metric in the toggle action caused the validation to silently fail, preventing the UI from updating.
