1 Overview

Goal: Restaurant owners need to know how much money they are making, what items are most popular, and they need a way to export this data for their accountant.

Key Deliverables

  • Financial KPIs: Total Revenue, Total Orders, and Average Order Value (AOV).
  • Visual Charts: A 14-day Revenue Timeline and a Top-5 Selling Items breakdown.
  • CSV Export: A one-click export button that generates a localized, Excel-compatible CSV file.
  • Server-Side Aggregation: Using Prisma's aggregate, groupBy, and raw SQL to do the heavy lifting in the database (not in JavaScript).

2 Database Aggregations (The "Senior" Approach)

Junior developers often fetch all orders into an array and use .reduce() to calculate revenue. This crashes at scale. We used PostgreSQL's native aggregation functions.

// Financial KPIs (Revenue, Orders, AOV)
const result = await prisma.order.aggregate({
  where: { status: { in: ["PAID", "PREPARING", "READY", "DELIVERED"] } },
  _sum: { totalAmount: true },
  _count: { id: true },
});

Raw SQL for Time-Series Data

Prisma doesn't natively support grouping by Date. To build the Revenue Timeline, we used a raw SQL query with DATE_TRUNC.

const result = await prisma.$queryRaw`
  SELECT 
    DATE_TRUNC('day', "createdAt") as date,
    SUM("totalAmount") as revenue
  FROM "orders"
  WHERE "status" IN ('PAID', 'DELIVERED') 
    AND "createdAt" >= NOW() - INTERVAL '14 days'
  GROUP BY DATE_TRUNC('day', "createdAt")
  ORDER BY date ASC;
`;

4 CSV Export & The UTF-8 BOM Trick

We built a Route Handler that generates a CSV file on the fly. However, we ran into a classic problem: Excel completely mangled the Arabic text.

The Excel Encoding Bug

Excel defaults to ANSI encoding when opening CSV files. Arabic text stored in UTF-8 turns into garbled characters (e.g., Ù…Ø³Ù‚Ø¹Ø©).

The Fix: We prepend a hidden Byte Order Mark (BOM) to the start of the CSV string. This tells Excel: "This file is UTF-8, read the Arabic properly!"

// Prepend the UTF-8 BOM (\uFEFF) to the CSV string
const csvString = "\uFEFF" + [headers.join(","), ...rows].join("\n");

return new NextResponse(csvString, {
  headers: {
    "Content-Type": "text/csv; charset=utf-8",
    "Content-Disposition": `attachment; filename="lumiere-orders.csv"`,
  },
});

We also ensured that the CSV export respects the current locale. If the admin is browsing in Arabic, the items are exported in Arabic. If in English, they are exported in English.

5 Engineering Lessons

  • Do the math in the database. Never load 10,000 records into memory just to calculate a sum. Use prisma.aggregate or raw SQL.
  • Recharts needs dir="ltr". Recharts gets very confused in RTL layouts. Forcing dir="ltr" on the chart container ensures the Y-axis stays on the left and the X-axis stays on the bottom, regardless of the page language.
  • Excel needs the BOM. If you are exporting any non-ASCII characters (Arabic, Chinese, emojis) to CSV, you must prepend \uFEFF or Excel will mangle it.
  • Route Handlers for downloads. For file downloads, always use a standard HTML <a> tag pointing to a Route Handler. Using Next.js <Link> will break the native download prompt.
