1 Overview

Goal: Security, stability, and observability. We ensured the app doesn't break, can't be spammed, and sends us an alert if something goes wrong.

Key Deliverables

  • End-to-End Testing: Playwright tests simulating the full customer journey.
  • CI/CD Pipeline: GitHub Actions automating builds and tests on every push.
  • Rate Limiting: Upstash Redis protecting server actions from abuse.
  • Error Tracking: Sentry monitoring production errors with full stack traces.

2 End-to-End Testing (Playwright)

We wrote comprehensive Playwright tests that simulate a customer adding an item to the cart, selecting Dine-In, and completing a Cash checkout.

Handling Next.js Server Actions Testing Server Actions requires intercepting the React Flight Stream. We used Playwright's route.fulfill with JSON payloads to safely test error states without crashing the React component.

3 CI/CD Pipeline (GitHub Actions)

Every push to main triggers a GitHub Actions workflow that builds the production app and runs the Playwright suite.

// .github/workflows/playwright.yml
steps:
  - uses: actions/checkout@v4
  - uses: actions/setup-node@v4
  - run: npm ci
  - run: npx prisma generate
  - run: npm run build  # <--- Builds production app
  - run: npx playwright test
Lazy Initialization for CI Top-level initializations like new Resend() and new Stripe() crash the CI build. We moved them inside the function bodies so they only initialize at runtime.

4 Rate Limiting (Upstash Redis)

We implemented a sliding window rate limiter in the createPendingOrder Server Action to prevent users from spamming the checkout endpoint.

import { Ratelimit } from "@upstash/ratelimit";
import { Redis } from "@upstash/redis";

export const rateLimiter = new Ratelimit({
  redis: Redis.fromEnv(),
  limiter: Ratelimit.slidingWindow(5, "1 m"),
});

If a user exceeds 5 requests in 1 minute, the Server Action returns a custom error that the UI displays as a red banner.

5 Observability (Sentry)

We integrated Sentry into the Next.js App Router to catch both client-side and server-side errors.

import * as Sentry from "@sentry/nextjs";

Sentry.init({
  dsn: process.env.NEXT_PUBLIC_SENTRY_DSN,
  tracesSampleRate: 1.0,
});

Sentry now captures unhandled exceptions in API routes, Server Actions, and React components, providing us with a live dashboard of production health.

6 Engineering Lessons

  • CI environments fail fast: Builds run in clean environments with no .env files. Always pass secrets via GitHub Actions env blocks.
  • Server Actions use Flight Streams: You cannot mock them with standard JSON. It's better to test the real action or use a component-level mock.
  • Rate limiters fail open: Redis timeouts allow the request through. Always configure a timeout and test the actual error state.
