Smart Table Assignment & Booking Pipeline

1 Overview

2 Architectural Decision — Pure Business Logic Separation

The problem: Where does "which table for this booking" logic belong?

LocationProsCons
Inside the Server ActionFewer filesUntestable without DB; mixes I/O with logic
Inside the Prisma modelReusableRequires ORM to exist
Separate pure functionTestable, portable, explainableOne extra file

Chosen approach: Pure function in src/lib/services/table-assignment.ts.

Engineering rationale
  • Testable without a database — a Node script exercises all rules in milliseconds.
  • Portable — the same function can run in a mobile app, a cron job, or a webhook handler.
  • Explainable to clients — logic is isolated in one file, not scattered across HTTP handlers.

3 The Four Business Rules

Input: (guestsCount, reservationDate, durationMinutes, tablesWithReservations)

Output: bestTable | null

1

Capacity Fit

Table seats the party, no more than 3 extra seats.

capacity >= guestsCount && capacity <= guestsCount + 3
2

No Time Overlap

Existing reservations must not intersect the new window.

existingStart < newEnd && existingEnd > newStart
3

Ranking

Smallest capacity first, then fewest existing reservations.

sort by capacity, then reservations.length
4

Active Only

Only tables flagged as active are considered.

isActive === true
Why "no more than 3 extra seats" A party of 2 should not occupy a 10-seat table. The buffer of 3 balances flexibility (small parties can use medium tables) against revenue loss (blocking a large table for a small party).

4 Interval Overlap Logic — The Math

The formula:

Overlap = (existingStart < newEnd) AND (existingEnd > newStart)

5 Touching Bookings Decision

The edge case: existing booking ends at 8:00, new booking starts at 8:00.

existingEnd (8:00) > newStart (8:00)  →  false  →  no overlap ✅

Why > not >=: Touching bookings are allowed. This is a business decision — the guest leaves, the next guest sits. No gap required.

Future enhancement (Phase 10) A 15-minute cleaning buffer can be added by changing the formula to existingEnd + 15min > newStart. Deferred to Polish phase.

9 Design in Pseudo-code

Before writing TypeScript, the algorithm in plain prose:

find_best_table(guestsCount, reservationDate, durationMinutes, tables):

  1. Compute newStart = reservationDate.timestamp
     Compute newEnd = newStart + durationMinutes * 60_000

  2. Filter tables where:
       - isActive == true
       - capacity >= guestsCount
       - capacity <= guestsCount + 3
       - No reservation overlaps [newStart, newEnd]

  3. If empty list → return null

  4. Sort candidates by:
       - capacity ascending (smallest first)
       - reservations.length ascending (least booked first)

  5. Return candidates[0]
Why pseudo-code first Catches logical gaps (e.g., "what if two tables tie?") before touching TypeScript. Saves rewrite cycles.

10 Types & Constants

export const DEFAULT_DURATION_MINUTES = 90;
export const CAPACITY_BUFFER = 3;

export type TableWithReservations = {
  id: string;
  number: number;
  capacity: number;
  location: string | null;
  isActive: boolean;
  reservations: {
    reservationDate: Date;
    durationMinutes: number;
  }[];
};

export type AssignmentRequest = {
  guestsCount: number;
  reservationDate: Date;
  durationMinutes?: number;
};
  • DEFAULT_DURATION_MINUTES = 90 — industry-standard dining duration; used when callers omit it.
  • CAPACITY_BUFFER = 3 — business rule extracted as a named constant (no magic numbers).
  • TableWithReservations — narrow shape the function needs, not the full Prisma model.
  • durationMinutes optional — callers may override the default.

Why define our own types instead of importing Prisma types: The function must run in contexts without Prisma (tests, future mobile app). Narrow input types keep it portable.

11 findBestTable Function

export function findBestTable(
  tables: TableWithReservations[],
  request: AssignmentRequest
): TableWithReservations | null {
  const duration = request.durationMinutes ?? DEFAULT_DURATION_MINUTES;

  const newStart = request.reservationDate.getTime();
  const newEnd = newStart + duration * 60_000;

  const candidates = tables
    .filter((table) => table.isActive)
    .filter(
      (table) =>
        table.capacity >= request.guestsCount &&
        table.capacity <= request.guestsCount + CAPACITY_BUFFER
    )
    .filter((table) => !hasOverlappingReservation(table, newStart, newEnd));

  if (candidates.length === 0) return null;

  candidates.sort((a, b) => {
    if (a.capacity !== b.capacity) return a.capacity - b.capacity;
    return a.reservations.length - b.reservations.length;
  });

  return candidates[0];
}

12 Function Deep-Dive

request.durationMinutes ?? DEFAULT_DURATION_MINUTES

?? (nullish coalescing) — falls back only if undefined or null. Why not ||: || would also replace 0, but a 0-minute reservation is invalid and should error upstream, not silently default.

getTime() for timestamp math

Returns milliseconds since Unix epoch (a number). Why numbers not Date objects: Numeric comparisons are faster; no timezone re-parsing; no accidental mutation.

60_000 instead of 60000

Underscore separator — pure readability, zero runtime effect.

Chained .filter() calls

Each filter is a single concern: active → capacity → overlap. Why not one giant filter: Chaining reads top-to-bottom like English; single && chains lose clarity.

Sort comparator

if (a.capacity !== b.capacity) return a.capacity - b.capacity;
return a.reservations.length - b.reservations.length;
  • Primary sort: capacity ascending.
  • Tiebreaker: fewest existing reservations (load balancing).

13 hasOverlappingReservation

function hasOverlappingReservation(
  table: TableWithReservations,
  newStart: number,
  newEnd: number
): boolean {
  return table.reservations.some((reservation) => {
    const existingStart = reservation.reservationDate.getTime();
    const existingEnd = existingStart + reservation.durationMinutes * 60_000;
    return existingStart < newEnd && existingEnd > newStart;
  });
}

Why .some() instead of .filter().length > 0: .some() short-circuits on the first match — returns immediately. .filter() scans all elements even after finding one.

Why this is a separate function: Single responsibility — overlap logic isolated from filtering. Reusable if other code paths (e.g., cancel-reservation check) need it.

18 Result State Pattern — Discriminated Union

type Result =
  | { kind: "idle" }
  | { kind: "submitting" }
  | { kind: "success"; tableNumber: number; reservationId: string }
  | { kind: "error"; message: string; fieldErrors?: Record<string, string[]> };

Why a discriminated union:

  • Impossible states are unrepresentable — you cannot have success without a tableNumber.
  • TypeScript narrows the type inside if (result.kind === "success").
  • Prevents result.message access when the state is success.

TIME_SLOTS generation

21 slots from 12:00 to 22:00 every 30 minutes. String(h).padStart(2, "0") → "09" not "9" — matches HTML <input type="time"> format. Why not a native time picker: Native time pickers differ per browser; a curated <select> enforces business hours visually.

handleChange name-based pattern

const { name, value } = e.target;
setFormData((prev) => ({ ...prev, [name]: value }));

One handler for 7 fields. Adding a new field requires zero handler changes — just name="..." on the input.

20 Zod Schema — reservation.ts

import { z } from "zod";
import { DEFAULT_DURATION_MINUTES } from "@/lib/services/table-assignment";

export const reservationSchema = z.object({
  guestName: z.string().trim()
    .min(2, "الاسم قصير جداً (حرفان على الأقل)")
    .max(80, "الاسم طويل جداً (80 حرفاً كحد أقصى)"),

  guestEmail: z.string().trim().toLowerCase()
    .email("البريد الإلكتروني غير صحيح"),

  guestPhone: z.string().trim()
    .min(8, "رقم الهاتف قصير جداً")
    .max(20, "رقم الهاتف طويل جداً")
    .regex(/^[+\d\s\-()]+$/, "رقم الهاتف يحتوي على رموز غير مسموحة"),

  guestsCount: z.coerce.number().int("عدد الأشخاص يجب أن يكون رقماً صحيحاً")
    .min(1, "على الأقل شخص واحد")
    .max(10, "لا يمكن الحجز لأكثر من 10 أشخاص"),

  date: z.string().regex(/^\d{4}-\d{2}-\d{2}$/, "التاريخ غير صحيح"),
  time: z.string().regex(/^\d{2}:\d{2}$/, "الوقت غير صحيح"),

  notes: z.string().trim()
    .max(500, "الملاحظات طويلة جداً (500 حرف كحد أقصى)")
    .optional().or(z.literal("")),
})

Why z.coerce.number() for guestsCount: HTML forms submit all values as strings, even <select> numbers. coerce runs Number(value) before validation.

Why Arabic error messages: Zod errors surface directly to the user — no translation layer needed. One source of truth for validation messages.

Why .trim() first: " أحمد " becomes "أحمد" before length check. Prevents bypass via whitespace padding.

21 Custom Refinements — Business Logic in Zod

.refine(
  (data) => {
    const dt = new Date(`${data.date}T${data.time}:00`);
    return dt.getTime() > Date.now();
  },
  { message: "لا يمكن الحجز في وقت ماضٍ", path: ["date"] }
)
.refine(
  (data) => {
    const dt = new Date(`${data.date}T${data.time}:00`);
    const hours = dt.getHours();

Why .refine() twice at the end:

  • Refinements run after all field validations pass.
  • Combines date + time into one check (cross-field validation).
  • path: ["date"] routes the error to the date field's error array.
The power of .refine() Zod is not just a type checker — it can enforce full business rules. These two refinements encode: "no bookings in the past" and "operating hours 12:00–22:00".

23 createReservation — Server Action

"use server";

import { prisma } from "@/lib/prisma";
import { reservationSchema, parseReservationDate } from "@/lib/validations/reservation";
import { findBestTable, DEFAULT_DURATION_MINUTES } from "@/lib/services/table-assignment";

export type CreateReservationResult =
  | { success: true; reservationId: string; tableNumber: number }
  | { success: false; error: string; fieldErrors?: Record<string, string[]> };

export async function createReservation(
  input: unknown
): Promise<CreateReservationResult> {
  const parsed = reservationSchema.safeParse(input);

  if (!parsed.success) {
    const fieldErrors: Record<string, string[]> = {};
    for (const issue of parsed.error.issues) {
      const key = issue.path.join(".") || "_";
      (fieldErrors[key] ??= []).push(issue.message);
    }
    return { success: false, error: "تحقق من البيانات المُدخلة", fieldErrors };
  }

  const data = parsed.data;
  const reservationDate = parseReservationDate(data.date, data.time);
  const duration = DEFAULT_DURATION_MINUTES;

  try {
    const bufferMs = 3 * 60 * 60 * 1000;
    const windowStart = new Date(reservationDate.getTime() - bufferMs);
    const windowEnd = new Date(reservationDate.getTime() + duration * 60_000 + bufferMs);

    const tables = await prisma.table.findMany({
      where: {
        isActive: true,
        capacity: { gte: data.guestsCount, lte: data.guestsCount + 3 },
      },
      include: {
        reservations: {
          where: {
            status: { in: ["PENDING", "CONFIRMED"] },
            reservationDate: { gte: windowStart, lte: windowEnd },
          },
          select: { reservationDate: true, durationMinutes: true },
        },
      },
    });

    const bestTable = findBestTable(tables, {
      guestsCount: data.guestsCount,
      reservationDate,
      durationMinutes: duration,
    });

    if (!bestTable) {
      return {
        success: false,
        error: "لا توجد طاولة متاحة في هذا الوقت. جرّب وقتاً آخر أو تواصل معنا هاتفياً.",
      };
    }

    const reservation = await prisma.reservation.create({
      data: {
        guestName: data.guestName,
        guestEmail: data.guestEmail,
        guestPhone: data.guestPhone,
        guestsCount: data.guestsCount,
        reservationDate,
        durationMinutes: duration,
        status: "PENDING",
        notes: data.notes && data.notes !== "" ? data.notes : null,
        tableId: bestTable.id,
      },
    });

    return { success: true, reservationId: reservation.id, tableNumber: bestTable.number };
  } catch (error) {
    console.error("[createReservation] error:", error);
    return { success: false, error: "حدث خطأ غير متوقع أثناء الحجز. يرجى المحاولة لاحقاً." };
  }
}

Why "use server" at the top: Marks the file as a Server Action module. All exports become RPC endpoints callable from Client Components. Not a Route Handler — no URL, no HTTP method.

Why input: unknown not input: ReservationInput: A malicious client can send anything. unknown forces explicit runtime validation before type-narrowing.

(fieldErrors[key] ??= []).push(...): ??= initializes the array on first key occurrence. Multiple Zod issues may target the same field; we accumulate rather than overwrite.

24 Query Window Optimization — ±3 Hours

const bufferMs = 3 * 60 * 60 * 1000;
const windowStart = new Date(reservationDate.getTime() - bufferMs);
const windowEnd = new Date(
  reservationDate.getTime() + duration * 60_000 + bufferMs
);

Why not fetch all reservations: After months of operation, tables accumulate hundreds of historical rows. Loading them all on every booking is wasteful.

Why ±3 hours: Longest realistic reservation is 3 hours. Any existing booking outside this window cannot overlap.

Effect: Query time stays O(recent rows) instead of O(all rows).

Pre-filtering capacity in SQL

capacity: { gte: data.guestsCount, lte: data.guestsCount + 3 }

Same condition as the pure function, but applied at the database layer. Why duplicate the rule in two places: The DB filter reduces rows returned; the pure function filter is the authoritative check. Duplication is intentional for performance.

25 Status-Aware Filtering

status: { in: ["PENDING", "CONFIRMED"] }
  • CANCELLED reservations free the table — don't count them.
  • COMPLETED reservations are historical — don't count them.
  • Business logic encoded in the query, not in post-processing.

Notes field normalization

notes: data.notes && data.notes !== "" ? data.notes : null

Zod returns "" for empty optional strings. Prisma expects null for empty nullable columns. Prevents storing empty strings in the database — makes "has notes" queries simpler.
