Phase 19 · PDF Invoices & Kitchen Tickets

Document Engineering

Generate high-quality, printable PDF documents dynamically on the server. Deliver branded A4 receipts to customers and high-contrast Kitchen Tickets to chefs.

@react-pdf/rendererStreaming Custom FontsRTL PDFs

1 Overview

Goal: Complete the physical restaurant loop by generating real PDF documents. Customers get a branded receipt, and the kitchen gets a no-nonsense, high-contrast cooking ticket.

Key Deliverables

  • Customer Receipt: A beautifully branded A4 PDF with the Lumière gold accents, itemized list, and payment method.
  • Kitchen Ticket: A simplified, massive-font PDF with no prices, designed to be printed on thermal printers in the kitchen.
  • Server-Side Streaming: Generating PDFs on the fly via API routes without saving files to disk.
  • Custom Font Registration: Loading the Cairo font to properly support Arabic ligatures in PDFs.

2 React PDF Templates

We used @react-pdf/renderer to build the templates. Just like React Email, it uses absolute inline styles and Flexbox, but renders to a physical A4 page.

// src/lib/pdf/CustomerReceipt.tsx
const styles = StyleSheet.create({
  page: { padding: 40, fontFamily: "Cairo", fontSize: 10 },
  header: { borderBottomWidth: 2, borderBottomColor: "#c9a961" },
  // ...
});

3 Streaming API Routes

Instead of saving the PDF to a folder (which breaks on Vercel Serverless), we stream it directly to the browser.

import { renderToBuffer } from "@react-pdf/renderer";

const buffer = await renderToBuffer(<CustomerReceipt ... />);

return new NextResponse(new Uint8Array(buffer), {
  headers: {
    "Content-Type": "application/pdf",
    "Content-Disposition": `inline; filename="receipt.pdf"`,
  },
});

5 The Vercel Serverless Hurdle

Deploying PDF generation to Vercel Serverless is notoriously difficult. We encountered a specific error where Vercel's file tracer failed to bundle the underlying pdfkit dynamic chunks.

The Error Cannot find module './chunks/standardGlyphNames-DNHAb7rp.cjs'

Require stack: /var/task/node_modules/pdfkit/js/standard-fonts/Helvetica.cjs

Why it happens: pdfkit uses dynamically generated CJS chunks for its standard fonts. Vercel's bundler missed these chunks, causing a 500 error in production while working perfectly locally.

The Fix: `next.config.ts`

We must tell Webpack not to bundle pdfkit, and explicitly force Vercel's tracer to include the entire pdfkit/js folder (including the hidden chunks).

// next.config.ts
const nextConfig: NextConfig = {
  serverExternalPackages: ["pdfkit", "@react-pdf/renderer"],
  
  outputFileTracingIncludes: {
    "/api/orders/[id]/receipt": [
      "./node_modules/pdfkit/js/**/*", // <--- The magic fix
      "./public/fonts/**/*",
      "./messages/**/*",
    ],
    "/api/orders/[id]/ticket": [
      "./node_modules/pdfkit/js/**/*",
      "./public/fonts/**/*",
      "./messages/**/*",
    ],
  },
};

6 Engineering Lessons

  • PDFs are a different beast: CSS for the web (like Tailwind) does not work in PDFs. You must use StyleSheet.create from @react-pdf/renderer.
  • RTL Support: Just adding Arabic text is not enough. You must pass direction: "rtl" to the Page style, and ensure the font supports Arabic shaping/ligatures.
  • Serverless Bundling: When using third-party Node libraries on Vercel, always check if they use dynamic imports. If they do, you must explicitly include their internal folders in outputFileTracingIncludes.
  • Thermal Printers: Kitchen tickets must not have background colors, logos, or prices. High contrast (black and white) and massive font sizes (20pt+) are required for readability in a hot, busy kitchen.
