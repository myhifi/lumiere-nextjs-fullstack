Build a complete authentication system from scratch — no Google OAuth, no paid services, no black boxes. Uses Auth.js v5 with credentials, bcrypt password hashing, JWT sessions, Edge middleware, and a User table with role-based access.

Rationale: For a single-restaurant dashboard with a handful of staff, JWT is optimal. Revocation isn't critical — a role change or password reset takes effect on next login. If a session must be killed immediately, rotating AUTH_SECRET invalidates all JWTs at once.

5 Why NO PrismaAdapter?

What PrismaAdapter adds:

  • Account table — links OAuth accounts to users.
  • Session table — server-side sessions.
  • VerificationToken table — Magic Link tokens.

Why we skip it:

  • We use Credentials → no Account needed.
  • We use JWT → no Session table needed.
  • We use no Magic Link → no VerificationToken needed.
Result Three fewer tables, zero adapter imports, no stale @auth/prisma-adapter initialization cost. The package remains installed (harmless) but unused.

9 TypeScript Augmentation — next-auth.d.ts

import type { DefaultSession } from "next-auth";

declare module "next-auth" {
  interface Session {
    user: {
      id: string;
      role: string;
    } & DefaultSession["user"];
  }

  interface User {
    role: string;
  }
}

declare module "next-auth/jwt" {
  interface JWT {
    id: string;
    role: string;
  }
}

What declaration merging does: Extends Auth.js's built-in Session, User, and JWT interfaces. Enables session.user.role and session.user.id across the app without as casts everywhere.

Auth.js v5 beta caveat The JWT interface augments less reliably than Session in v5 beta. In the session() callback, we use a single token as { id: string; role: string } cast to bridge the gap. Documented as a Polish item for when v5 stabilizes.

10 Bcrypt Concepts — How Hashing Works

Why hashing (not encryption): Encryption is reversible — decrypt to get the original. Hashing is one-way — impossible to reverse. A leaked database of bcrypt hashes is effectively useless to attackers.

Bcrypt parameters

ParameterValueWhy
Salt128-bit randomUnique per password → same password produces different hashes
Rounds10 → 2¹⁰ = 1,024 iterations~50-400ms — slow enough to stop brute force, fast enough for users
Output60 charsFixed length regardless of input password length

Salt is embedded in the hash

$2b$10$NvjaWGsGkR9bq54pMMeZauWy3UIgHPYsTdwwX/mf6LqCyB9YauCW
 │   │  └─── 22-char salt + hash payload
 │   └────── cost factor (10)
 └────────── algorithm version (2b)

Verification flow

  1. Extract salt from stored hash.
  2. Hash the candidate password with the same salt.
  3. Compare byte-for-byte. If equal → match.

11 password.ts — Full File

import bcrypt from "bcryptjs";

export const BCRYPT_ROUNDS = 10;
export const MIN_PASSWORD_LENGTH = 8;

export async function hashPassword(plainPassword: string): Promise<string> {
  if (plainPassword.length < MIN_PASSWORD_LENGTH) {
    throw new Error(
      `كلمة السر قصيرة جداً (الحد الأدنى ${MIN_PASSWORD_LENGTH} أحرف)`
    );
  }
  return bcrypt.hash(plainPassword, BCRYPT_ROUNDS);
}

export async function verifyPassword(
  plainPassword: string,
  storedHash: string
): Promise<boolean> {
  try {
    return await bcrypt.compare(plainPassword, storedHash);
  } catch {
    return false;
  }
}
  • bcryptjs (not bcrypt) — pure JavaScript, no node-gyp compilation on Windows.
  • BCRYPT_ROUNDS = 10 — exported constant, changes propagate everywhere.
  • MIN_PASSWORD_LENGTH = 8 — enforces NIST/OWASP minimum at the utility layer.
  • verifyPassword wraps compare in try/catch — malformed hashes return false instead of throwing.
  • Both functions are async — bcrypt is CPU-intensive; async keeps the event loop responsive.

13 auth.config.ts — Edge-Safe Config

import type { NextAuthConfig } from "next-auth";

export const authConfig: NextAuthConfig = {
  session: {
    strategy: "jwt",
    maxAge: 30 * 24 * 60 * 60, // 30 days
  },
  pages: {
    signIn: "/login",
    error: "/login",
  },
  providers: [], // Populated in auth.ts
  callbacks: {
    async jwt({ token, user }) {
      if (user) {
        token.id = user.id as string;
        token.role = user.role;
      }
      return token;
    },
    async session({ session, token }) {
      const t = token as { id: string; role: string };
      session.user.id = t.id;
      session.user.role = t.role;
      return session;
    },
    authorized({ auth, request }) {
      const isOnAdmin = request.nextUrl.pathname.startsWith("/admin");
      if (isOnAdmin) return !!auth;
      return true;
    },
  },
};

Why this file is Edge-safe:

  • No prisma import.
  • No bcrypt import.
  • No node:* imports.
  • Only Auth.js types and callbacks that operate on plain objects.

14 The Edge Runtime Problem — Why Two Files?

Symptom observed during development Failed to load external module node:path: TypeError: Native module not found: node:path at src/lib/prisma.ts:8:1

The chain that broke:

middleware.ts (Edge Runtime)
    └── imports auth.ts
            └── imports prisma.ts
                    └── imports 'node:path'  ❌ Edge can't load Node built-ins
CapabilityEdge RuntimeNode Runtime
node:path, node:fs, node:crypto❌✅
Native .dll/.node binaries❌✅

The fix — split configuration auth.config.ts — Edge-safe (pages, session, callbacks). auth.ts — Node-only (extends config, adds Prisma-backed Credentials). Middleware imports only auth.config.ts. Result: Edge bundle shrinks from ~100 MB (with Prisma engine) to a few KB.

15 auth.ts — Node Runtime Config

import NextAuth from "next-auth";
import Credentials from "next-auth/providers/credentials";
import { z } from "zod";
import { prisma } from "@/lib/prisma";
import { verifyPassword } from "@/lib/auth/password";
import { authConfig } from "./auth.config";

const credentialsSchema = z.object({
  email: z.string().trim().toLowerCase().email(),
  password: z.string().min(1),
});

export const { handlers, signIn, signOut, auth } = NextAuth({
  ...authConfig,
  providers: [
    Credentials({
      credentials: {
        email: { label: "البريد", type: "email" },
        password: { label: "كلمة السر", type: "password" },
      },
      async authorize(rawCredentials) {
        const parsed = credentialsSchema.safeParse(rawCredentials);
        if (!parsed.success) return null;

        const { email, password } = parsed.data;
        const user = await prisma.user.findUnique({ where: { email } });
        if (!user) return null;
        if (!user.isActive) return null;

        const isValid = await verifyPassword(password, user.passwordHash);
        if (!isValid) return null;

        prisma.user.update({
          where: { id: user.id },
          data: { lastLoginAt: new Date() },
        }).catch(() => {});

        return {
          id: user.id, email: user.email,
          name: user.name, role: user.role,
        };
      },
    }),
  ],
});

16 authorize() Deep-Dive — Security Layers

The five returns of null:

1
if (!parsed.success) return null;
Malformed input — Zod catches bad shapes first.
2
if (!user) return null;
Email not found — cannot leak whether the account exists.
3
if (!user.isActive) return null;
Account disabled — terminated employees cannot log in.
4
if (!isValid) return null;
Wrong password — bcrypt compare returned false.
→ Auth.js converts all nulls into a generic "CredentialsSignin" error

This prevents User Enumeration Attacks

Different messagesSame message (ours)
Attacker learns which emails existAttacker learns nothing
Can target known accountsMust guess blindly

Side effect — lastLoginAt update

  • Fired but not awaited (fire-and-forget).
  • .catch(() => {}) swallows errors — a logging failure must not block login.
  • Runs in parallel with the response serialization.

18 LoginForm — Client Component

"use client";

import { useState, type FormEvent } from "react";
import { signIn } from "next-auth/react";
import { useRouter, useSearchParams } from "next/navigation";
import { FormField, inputClasses } from "@/components/ui/FormField";

type Result =
  | { kind: "idle" }
  | { kind: "submitting" }
  | { kind: "error"; message: string };

export function LoginForm() {
  const router = useRouter();
  const searchParams = useSearchParams();
  const callbackUrl = searchParams.get("callbackUrl") ?? "/admin";

  const [email, setEmail] = useState("");
  const [password, setPassword] = useState("");
  const [result, setResult] = useState<Result>({ kind: "idle" });

  async function handleSubmit(e: FormEvent) {
    e.preventDefault();
    setResult({ kind: "submitting" });

    const response = await signIn("credentials", {
      email, password, redirect: false,
    });

    if (!response || response.error) {
      setResult({
        kind: "error",
        message: "البريد الإلكتروني أو كلمة السر غير صحيحة",
      });
      return;
    }

    router.push(callbackUrl);
    router.refresh();
  }

  /* JSX continues */
}

19 LoginForm Deep-Dive — redirect: false

redirectBehavior on failure
true (default)Browser jumps to /login?error=CredentialsSignin
false (ours)Function returns { error: "..." }; we render Arabic message

Why we override:

  • Auth.js's default error page is English and generic.
  • We need Arabic text styled to match Lumière.
  • Full control over navigation timing (push then refresh).

router.refresh() — the less-obvious necessity

After router.push(callbackUrl), the URL changes but cached Server Components still hold old session data. The Navbar won't show the user's name, and any server-side session read returns null.

router.refresh() forces Next.js to re-fetch all Server Components for the current route. Combined with the newly-set JWT cookie, they re-render with the session.

router.push(callbackUrl);  // navigate first
router.refresh();          // then invalidate

21 middleware.ts — Edge Guard

import NextAuth from "next-auth";
import { authConfig } from "./auth.config";

export default NextAuth(authConfig).auth;

export const config = {
  matcher: ["/admin/:path*"],
};

Why not import { auth } from "@/auth":

  • That module imports Prisma.
  • Prisma cannot load in Edge Runtime.
  • We instantiate a fresh NextAuth(authConfig) — Edge-safe by construction.

How redirection happens

  • The authorized callback (in auth.config.ts) returns false for unauthenticated /admin requests.
  • Auth.js automatically redirects to pages.signIn (/login).
  • callbackUrl is preserved via Auth.js's internal cookie.

23 create-admin.ts — Idempotent Seeder

import "dotenv/config";
import { PrismaClient } from "../src/generated/prisma/client";
import { hashPassword } from "../src/lib/auth/password";

const prisma = new PrismaClient();

const ADMIN_DATA = {
  email: "admin@lumiere.com",
  password: "Admin@Lumiere2026",
  name: "مدير Lumière",
  role: "ADMIN",
};

async function main() {
  const passwordHash = await hashPassword(ADMIN_DATA.password);

  const admin = await prisma.user.upsert({
    where: { email: ADMIN_DATA.email },
    update: { passwordHash, name: ADMIN_DATA.name, role: ADMIN_DATA.role, isActive: true },
    create: { email: ADMIN_DATA.email, passwordHash, name: ADMIN_DATA.name, role: ADMIN_DATA.role, isActive: true },
  });

  console.log("✅ تم بنجاح:");
  console.log(`   ID:      ${admin.id}`);
  console.log(`   البريد:  ${admin.email}`);
}

main()
  .catch((error) => { console.error("❌ خطأ:", error); process.exit(1); })
  .finally(async () => { await prisma.$disconnect(); });

Concernseed.tscreate-admin.ts
Deletes data first✅ Yes❌ No
IdempotentNo✅ Yes (upsert)
Safe to re-run❌✅
PurposeDemo dataFirst admin

upsert semantics: create if missing, update if present. Running the script twice updates the admin's password rather than failing on a unique constraint.

24 Auth Flow Trace — Login with Valid Credentials

1. User opens /login
2. Submits admin@lumiere.com / Admin@Lumiere2026
3. signIn("credentials", { redirect: false }) fires
─── HTTP POST /api/auth/callback/credentials ───
4. Route Handler → Auth.js:
a. Read AUTH_SECRET from .env
b. Execute authorize() with email + password
c. Zod validates shape
5. prisma.user.findUnique({ where: { email } })
6. verifyPassword(password, user.passwordHash) → true
7. Fire-and-forget update lastLoginAt
8. Return { id, email, name, role }
9. Auth.js creates JWT with those fields
10. Sets encrypted cookie: authjs.session-token
11. Responds 200 to the client
─── CLIENT ───
12. router.push("/admin") → middleware intercepts
13. middleware reads JWT cookie → authorized() → true
14. router.refresh() invalidates Server Component caches

Boundary guarantees:

  • Passwords never leave the server in plaintext (only over HTTPS in production).
  • JWT cookie is HTTP-only + Secure (in production) + SameSite=Lax.
  • Prisma is never imported into client bundles.
