1 Overview

10 Step 5: Vercel Connect

Import flow from the Vercel dashboard:

  1. Click Add New → Project.
  2. Select the GitHub repository lumiere-nextjs-fullstack.
  3. Confirm Framework Preset = Next.js (auto-detected).
  4. Leave Root Directory as ./.
  5. Add the four environment variables before clicking Deploy.
  6. Do not enable the Optional Integrations — they would override manual configuration.
Trap avoided Vercel offers "Prisma Postgres" and "Resend email" integrations in the setup page. Both would create new accounts and override the manually configured values. Manual configuration gives full control.

Why direct URL and not pooler? Vercel Serverless functions establish short-lived connections. Neon's PgBouncer pooler, designed for long-lived connections, was refusing these short-lived handshakes with P1001. Direct endpoint works flawlessly. For low-traffic portfolios, direct connections consume only 1–3 of the 100-connection limit.

13 The 5 Errors Journey

Production deployment revealed five distinct errors — each requiring a different fix. This is the complete timeline.

🎯 Error 1: Missing force-dynamic

Error occurred prerendering page "/" · Can't reach database server
Fix: Add export const dynamic = "force-dynamic" to DB-driven pages.

🎯 Error 2: TypeScript Declaration Missing

Could not find a declaration file for module '@prisma/nextjs-monorepo-workaround-plugin'
Fix: Create src/types/prisma-plugin.d.ts with declare module.

🎯 Error 3: Turbopack vs Webpack Conflict

This build is using Turbopack, with a `webpack` config and no `turbopack` config
Fix: Add --webpack flag to both dev and build scripts.

🎯 Error 4: Query Engine Missing on Vercel

Prisma Client could not locate the Query Engine for runtime "rhel-openssl-3.0.x"
Fix: Switch from prisma-client to prisma-client-js generator.

🎯 Error 5: Pooler Failure

Can't reach database server at `ep-delicate-queen-api0jkos-pooler.c-7.us-east-1.aws.neon.tech:5432`
Fix: Replace -pooler hostname with direct endpoint in Vercel env vars.

14 Error 1: force-dynamic

Symptom:

⨯ Error [PrismaClientInitializationError]:
  Can't reach database server at `ep-delicate-queen-api0jkos-pooler...`
  at async i (src/app/(public)/page.tsx:7:25)
Export encountered an error on /(public)/page: /, exiting the build.

Root cause: Next.js tried to prerender the homepage at build time — querying the database during deployment. Neon refused the connection because it was cold.

Fix: Add export const dynamic = "force-dynamic" to every page that queries the database.

// src/app/(public)/page.tsx
import { prisma } from "@/lib/prisma";

export const dynamic = "force-dynamic";    // ← added

export default async function HomePage() {
  const featuredItems = await prisma.menuItem.findMany(...);
  ...
}
Result Pages render on-demand instead of at build. First visitor triggers the DB query; subsequent visitors hit cached HTML.

15 Error 2: TypeScript Declaration

Symptom:

Could not find a declaration file for module 
'@prisma/nextjs-monorepo-workaround-plugin'.

Root cause: The plugin has no TypeScript type definitions, so the import statement failed during next build's type check.

Fix: Create a declaration file.

// src/types/prisma-plugin.d.ts
declare module "@prisma/nextjs-monorepo-workaround-plugin";
Pattern for future use Whenever a third-party library lacks types, create a one-line .d.ts file under src/types/ with declare module "library-name".

16 Error 3: Turbopack vs Webpack

Symptom:

⨯ ERROR: This build is using Turbopack, with a `webpack` config 
   and no `turbopack` config.
   This may be a mistake.

Root cause: Next.js 16 defaults to Turbopack. Turbopack cannot use the webpack() function from next.config.ts where PrismaPlugin is injected. The two build systems are fundamentally incompatible.

Fix: Force Webpack in both dev and production.

"scripts": {
  "dev":   "next dev --webpack",
  "build": "next build --webpack"
}
Trade-off Webpack builds are ~10–15 seconds slower than Turbopack but are the only way to run custom webpack() configuration — required for PrismaPlugin.

17 Error 4: Query Engine Missing

Symptom:

Prisma Client could not locate the Query Engine for runtime "rhel-openssl-3.0.x".
...
Ensure that "libquery_engine-rhel-openssl-3.0.x.so.node" 
has been copied to ".next/server/chunks".

The following locations have been searched:
  /var/task/.next/server/chunks
  /vercel/path0/src/generated/prisma
  /tmp/prisma-engines

Root cause: The prisma-client generator (Prisma 6's newer style) outputs to a custom directory src/generated/prisma/. Next.js excludes this directory from build outputs because it's gitignored. The Linux .so.node binary never reached the Vercel runtime.

Fix: Switch to the classic prisma-client-js generator, which outputs to node_modules/@prisma/client/ — a directory Next.js automatically includes in builds.

GeneratorOutputVercel Bundle
prisma-clientsrc/generated/prisma/ (gitignored)❌ Missing engine
prisma-client-jsnode_modules/.prisma/client/ (auto-bundled)✅ Engine included
 
generator client {
  provider      = "prisma-client-js"
  binaryTargets = ["native", "rhel-openssl-3.0.x"]
}

Required import changes

All files that imported from ../generated/prisma/client had to switch to @prisma/client:

  • prisma/seed.ts
  • scripts/create-admin.ts
  • src/lib/prisma.ts

18 Error 5: Pooler Failure

Symptom (runtime, after successful build):

prisma:error 
Invalid `prisma.menuItem.findMany()` invocation:

Can't reach database server at 
`ep-delicate-queen-api0jkos-pooler.c-7.us-east-1.aws.neon.tech:5432`

Root cause: The -pooler hostname uses PgBouncer, which is optimized for long-lived connections (traditional server deployments). Vercel Serverless opens and closes connections per request. PgBouncer rejects the rapid handshake sequence with a P1001 timeout.

Diagnostic confirmation:

  • Neon dashboard showed compute as ACTIVE — not a cold start.
  • Local development with direct URL worked perfectly.
  • Only Vercel (serverless) failed on the pooled endpoint.

Fix: Update Vercel's environment variables to use the direct endpoint.

❌ Broken (Pooled)
ep-delicate-queen-api0jkos-pooler.c-7.us-east-1.aws.neon.tech
✅ Working (Direct)
ep-delicate-queen-api0jkos.c-7.us-east-1.aws.neon.tech
Why this works for low-traffic portfolios Direct connections consume 1–3 of Neon's 100-connection limit. For a portfolio site with occasional visitors, this is negligible. Pooler becomes necessary only at high concurrency.
